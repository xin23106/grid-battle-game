# 英雄战棋 · 夹击战术

一个运行在浏览器里的 **6×6 回合制战棋**游戏：夹击战术、**18 名差异化英雄**、专属技能与被动、锦囊系统、打击音效，
支持 **本地双人对战 / AI 人机对战 / 在线真人联机**。

- 纯前端（原生 HTML / CSS / JavaScript，**无需构建**），打开即玩。
- 在线联机额外需要一个轻量 **Node.js + ws** 权威服务器（可选）。

## 二、功能一览

- 🎯 **夹击战术**：只看上下左右，正相对 / 直角 / 靠墙都能触发；含「队友保护」抵消。
- 🦸 **18 名英雄**，各自 1 个主动技能（部分含被动 / 双段 / 多段技能），数值与规则全部集中在 `heroes.js`。
- ⚔️ **阿修罗·剑圣 + 锻剑**：突进集剑闭环（消耗剑 → 阵亡留剑 → 踩上回收）。
- 🔪 **刺客·追猎 / 吸血鬼·血崩**：命中即标记、击杀刷新次数。
- 🎴 **锦囊系统**：6 种锦囊，开局随机抽取，不占行动，一局一次。
- 🤖 **三档难度 AI**：用与真人完全相同的规则接口枚举并打分，不依赖任何外部 API。
- 🌐 **在线真人联机**：Node 权威服务器（房间 / 准备 / 回合同步 / 规则校验 / 分享链接）。
- 🔊 **打击音效 / 背景音乐**：Web Audio 实时合成，每英雄独立音色，无外部音频文件与版权问题。
- 📱 **响应式界面**：窄屏自动堆叠、棋盘居中。

## 三、玩法与规则

- 棋盘 6×6，双方各在半场放置 **3 名英雄**（同阵营不可重复），生命值档位 5/6/7/8。
- **回合**：每回合操作 **一名** 己方英雄，完成 **1 次正常行动**（移动一格 / 普通攻击 / 技能）。
  **行动后回合不会自动结束**——仍停留在当前回合，可以继续使用**锦囊** / **「不耗步」技能** / **行军令的额外移动**，
  然后手动点 **「结束回合」** 交给对方（按钮会变绿提示「结束回合 ▶」）。
  **不能一上来就直接跳过**：回合开始时「结束回合」按钮为禁用，必须先行动；仅当确实无行动可做（如全被冰封）时才允许结束（防死锁）。
- **不耗步技能**：例如阿修罗·剑圣**不占用正常行动**，因此「先移动/普攻 → 再突进」可在同一回合完成。
- **夹击（只看上下左右）**：目标每个相邻敌人、以及每侧紧贴的棋盘边界（墙）各算 1 个「夹击方向」；相邻 ≥1 敌人且方向总数 **≥2** 即触发；加伤 =（方向数 − 1）。**技能不受夹击加成**。
- **队友保护**：目标相邻存在未被夹击的队友时，夹击无效。
- **普通攻击**：只打相邻敌人，基础伤害 1（夹击 / 猛攻令 / 被动等加成另计）。**若这次普通攻击最终击败目标，攻击者会立即占据目标原本所在的格子**（在伤害 / 护盾 / 闪避 / 死亡全部结算之后判定；夹击击杀同样生效）。仅**普通攻击**适用——**技能伤害、击退拉取、持续伤害等不会**让攻击者移动。若目标格被剑刃等占据或攻击者无法移动，则按现有合法位移规则**不移动**（不产生重叠）。
- **技能**：无冷却，只有**释放次数**限制。
- **胜负**：消灭对方全部英雄即获胜。

### 锦囊系统

- 开局双方各**随机获得一张锦囊**；每张只能在本局使用**一次**；**不占用正常行动**；只能在**自己的回合**使用。
- 需要选目标的锦囊会进入选择状态，非法目标**不消耗**且可重新选择；使用后立即生效并更新界面。
- **联机**：锦囊在**使用前**对对手保密；**成功使用后**，服务端向双方公开**本次使用的具体名称**与公开结算结果，双方对战日志记录同一条；未使用的锦囊继续保密。

| 锦囊 | 效果 |
| --- | --- |
| 猛攻令 🔥 | 本回合己方造成的伤害 **+1**（普攻 / 技能 / 剑圣） |
| 还魂令 💫 | 复活一名本局阵亡的己方英雄（恢复 3 血，**不重置技能次数**）。**优先在原位置**；若原位置已被占据（例如击杀者已站上该格），自动改为**最近的空格** |
| 行军令 🐎 | 使用后，本回合结束立刻获得一个【**额外回合**】（完整行动机会：移动 / 攻击 / 技能；技能次数按各自规则结算），该回合结束才轮到对手。不占用正常行动 |
| 技能重整令 ♻️ | 己方一名存活英雄技能次数恢复至**上限**（不改变生命 / 携带剑数） |
| 坚守令 🛡️ | 己方英雄在对手的**下一个回合**受到的每次伤害 **-1**（最低 0） |
| 战地急救令 ➕ | 选择一名生命未满的己方英雄，恢复 **2 点**生命（不超上限） |

- 每局重新开始会**重新抽取**并清空全部临时效果；AI 会根据战局使用锦囊；联机时由**服务器权威**校验与结算。
- 锦囊配置集中在 `talismans.js`（服务器用 `server/talismans.js`），新增锦囊只需加配置 + 对应效果分支。

### 阿修罗机制

- **剑圣（主动，不耗步）**：沿上下左右方向突进最多 **3 格**；途经敌人各受 **1 点**伤害；我方英雄会阻挡路径；若前方三格全是敌人则**原地斩击**；突进沿途经过的剑刃会一并回收。
  - **不占用本回合的正常行动**（可在移动/普攻后再突进）。
  - **每回合最多 2 次**（回合开始恢复）。
  - **每次消耗 1 把剑**；**没有剑时无法发动**。
- **锻剑（被动）**：阿修罗存活时，任意英雄阵亡都会在其位置**留下一把剑**；阿修罗移动到剑上即可**回收**（携带剑数 +1）。剑在地图上像墙体一样阻挡移动，其他英雄不能回收。

## 五、游戏模式

- **本地双人对战**：同一设备轮流操作。
- **AI 人机对战**：选择难度（简单/普通/困难）与自己的阵营，电脑接管另一方。
  - 轻量战术 AI（**不依赖任何外部 API**），用与真人相同的规则接口枚举合法行动并打分：
    击杀 > 有效伤害 > 夹击 > 技能价值 > 靠近敌人 > 回收剑刃，并对危险位置、被夹击风险、来回踱步扣分；
    三档难度用**权重 + 随机度**真实区分。AI 遵守「必须先行动、不能直接跳过回合」等规则。
- **在线真人对战**：见下文，需要额外运行 `server/`。

## 六、本地运行

### 一键启动（Windows，推荐）

双击项目根目录的 **`启动游戏.bat`**，它会自动启动网页服务（`serve.py`，**禁用缓存**）、
尝试启动联机服务器（`server/server.js`），并用浏览器打开游戏。

### 手动启动

```bash
# 1) 网页服务（本地静态服务，禁用缓存）
python serve.py            # 默认 http://localhost:8765/index.html

# 2) 联机服务器（仅在线真人对战需要）
cd server
npm install                # 仅第一次
node server.js             # 默认 ws://0.0.0.0:3000
```

然后浏览器打开 <http://localhost:8765/index.html>。

> 也可直接双击 `index.html` 离线玩单机 / AI；用 `serve.py` 可避免改动后浏览器缓存不刷新。

### 依赖与构建

- 前端：**无构建、无依赖**（原生 HTML/CSS/JS）。任何静态服务器都能托管。
- 后端（可选）：Node.js ≥ 18，唯一依赖 [`ws`](https://www.npmjs.com/package/ws)（MIT）。`npm install` 后 `npm start`。
- 本项目**不需要任何环境变量 / 密钥**。若你自行接入第三方 API，请放在服务端代理，切勿写进前端。

## 十、在线联机（进阶）

服务器是**权威**：客户端只提交行动，服务器校验并执行后广播最新状态，**客户端不能提交棋盘/伤害结果**。

### 同一局域网

1. 主机运行 `启动游戏.bat`（或 `node server/server.js`），并在防火墙弹窗选“允许”（或管理员执行
   `netsh advfirewall firewall add rule name="gridbattle-ws" dir=in action=allow protocol=TCP localport=3000`）。
2. 两台设备都用主机的局域网地址打开游戏，例：`http://192.168.x.x:8765/index.html`。
3. 菜单 →「在线真人对战」→ 徽标变绿「已连接服务器」→ 一方「创建房间」→ 另一方「加入房间」→ 双方「我准备好了」。

### 分享链接

创建房间后会显示一条**分享链接**（形如 `http://<主机IP>:8765/index.html?room=ABCDE&server=ws://<主机IP>:3000`），
发给好友**点开即自动进房**（链接里一定会带上服务器地址，好友打开后无需任何设置）。

- 若主机同时有多个地址（例如**局域网 IP** 与 **VPN 地址**），下方会出现「**分享地址**」下拉框，选对地址后链接自动更新。
- 好友点开后若 **8 秒内连不上**，页面会直接提示排查步骤（同一网络 / 放行端口 / 手动粘贴服务器地址）。

### 手机 / 平板加入

1. 手机连**和电脑同一个 Wi-Fi**；2. 电脑放行 **8765** 与 **3000** 端口；3. 路由器没开「AP 隔离」。
   - 手机用移动流量、或连别的 Wi-Fi，都打不开内网地址；多数 VPN（如 Radmin）没有手机版。
   - 同一 Wi-Fi 仍不行通常是 **AP 隔离**，请改用内网穿透（cloudflared / ngrok）。

### 跨网络

- **内网穿透**（cloudflared / ngrok）：把网页与服务器各开一条隧道，网页用网页隧道地址打开，游戏内填 `wss://<ws隧道域名>`。
- **公网部署**：把前端与 `server/` 放到有公网 IP 的机器，用 HTTPS + `wss://`。

### 临时公网隧道（cloudflared，免注册，最快）

不想注册任何平台时，可以在本机开一条临时隧道，**立刻**让好友联机：

1. 双击 **`开联机隧道.bat`**（cloudflared 已装在本机 `%LOCALAPPDATA%\cloudflared\`）。
2. 窗口里会打印 `https://xxxx.trycloudflare.com`，对应的**联机地址**是 `wss://xxxx.trycloudflare.com`。
3. 打开游戏 →「在线真人对战 → 服务器」填入该地址 →「连接」→「创建房间」→ 复制**分享链接**发给好友，点开即进房。

- ⚠️ 临时隧道地址**每次重启都会变**；变了重新填一次即可。
- ⚠️ 需要本机**一直开着**（游戏服务器 `node server.js` + 隧道窗口都不能关）。
- `net.js` 顶部的 `CLOUD_SERVER` 常量用于给**公网页面**指定默认服务器地址；隧道地址变了改这一行并推送即可。

### 联机专属规则：随机选将 · 隐藏部署 · 锦囊保密

联网真人对战与单机 / AI 不同——为公平起见由**服务端**执行以下机制：

1. **随机选将（服务端抽取）**：双方进入布阵阶段时，**服务器独立随机抽取 3 名不重复英雄**作为各自候选池（英雄足够时双方池不重复）。候选池本局固定，**刷新 / 断线重连 / 重复请求都不会重抽**；客户端**只能部署自己候选池内的英雄**。
2. **隐藏式部署**：双方**同时、各自独立**布阵。布阵阶段**看不到**对手的候选池、已选英雄、部署位置与顺序——对手面板只显示「对手：部署中 / 已准备」。**双方都完成部署后**服务端才开战，开战后按正常规则公开战场英雄信息。
3. **锦囊保密**：锦囊名称、说明与使用状态**只下发给持有者本人**；对手最多看到一句中立提示「对手使用了一张锦囊」，具体名称与效果不泄露（实际战斗结果照常公开）。
4. **服务端隔离（非前端隐藏）**：服务器为每位玩家分别保存候选池 / 部署 / 锦囊，并按接收者身份生成**不同的可见状态**——对手的候选池、布阵阶段的对半场单位与锦囊在**网络响应里就是 null / 不存在**，不依赖 CSS 隐藏。所有部署与锦囊请求都由服务端校验归属、候选池、半场、次数与回合。

> 想体验：双方各自打开游戏 →「在线真人对战」→ 一方建房、另一方加入 → 双方「我准备好了」→ 各自从自己的 3 名候选中部署。

### 部署联机服务器到公网（免费，推荐 Render）

部署后**任何人点开分享链接就能联机**（不必在同一局域网）。仓库里已经准备好了部署配置，基本是"点几下"：

1. 用 **GitHub 账号登录** <https://render.com>（免费，不需要信用卡）。
2. 控制台 → **New → Blueprint** → 选择本仓库 `grid-battle-game` → **Apply**。
   （仓库根目录已有 `render.yaml`，会自动读取 `server/` 作为服务、`node server.js` 启动、健康检查 `/`。）
3. 等构建完成，得到形如 **`https://grid-battle-server-xxxx.onrender.com`** 的地址。
4. 打开游戏 →「在线真人对战」→「**服务器**」填入该地址（填 `https://…` 或 `wss://…` 都行，会自动换算）→「连接」→「创建房间」→ 复制**分享链接**发给好友。
5. 好友点开链接即自动连接并入房，双方点「我准备好了」即可开打。

其他平台也可：
- **Railway / Heroku 类**：`server/Procfile` 已写好（`web: node server.js`）。
- **Fly.io / 任意容器平台**：`server/Dockerfile` 已写好（`docker build -t grid-battle-server ./server`）。
- 平台的端口由环境变量 `PORT` 注入，服务器已自动适配（默认 3000）。

> ⚠️ Render **免费实例闲置约 15 分钟会休眠**，好友首次连接需要等 ~30–60 秒唤醒，属正常现象。
> ⚠️ 页面是 HTTPS 时，联机地址必须是 **`wss://`**（游戏会自动把 `ws://` 升级为 `wss://`）。

## 十一、音效与设置

- **纯程序化合成音效（无外部音频文件、无版权风险）**：由 Web Audio 的振荡器 + 噪声 + 非谐波金属泛音 + 低频冲击组合而成，每个音效是**多层配方**，不是同一个音频换音量/变速。
- **每名英雄有独立音色**（`HERO` 表：波形 / 基频 / 破风频段 / 金属泛音 / 低频厚度），作用于出手、命中与技能层。
- **普通战斗事件分层**：轻击 / 重击 / 快攻 / 夹击 / 轻受击 / 重受击 / 护盾吸收 / 护盾破碎 / 闪避 / 死亡 / 复活 / 治疗 / 护盾生成 / 强化开启与结束 / 击退 / 抓取 / 标记 / 锻剑 / 拾剑 / 锦囊 / 胜负，各自独立配方。
- **技能专属配方**：伤害单体、冰封、治疗、横扫、穿透、护盾、瞬移、剑圣突进、断浪、水调歌头、龙息、雷霆万钧、追猎（飞镖/瞬步）、血崩（含吸血）、紫薇神步、放逐、天威、神罗天征、万象天引（三段各不相同）、被动。
- **变体与限流**：普通攻击 5 个变体、命中 5 个变体、死亡/受击/护盾各有变体池；随机选择且**不会连续重复**同一变体。按事件节流（40–500ms）、按“层”限制最大同时发声数（64），声音多时自动压低单层音量。
- **持续音管理**：雷电之主强化有极轻的电流底音，`startLoop/stopLoop` 带淡出；强化结束、雷电阵亡、胜负结算、新开一局、静音都会停止，绝无残留。
- **音效与真实结算同步**：出手在挥击时、命中在伤害结算时、闪避只在成功闪避时、护盾只在真实吸收时、死亡只在真实阵亡时、治疗只在真正回血时、标记只在真正标上时；技能音效在结算成功后才播放（取消 / 非法目标 / 次数不足不发声）。
- **联机**：服务端仍权威；客户端只按“日志新 id + 状态差异”派生音效，重复广播 / 重连不会重复播放。
- **设置**（自动保存）：战斗音效开关、技能音效开关、战斗音效音量、主音量、试听、恢复默认；静音时显示状态提示，滑块实时生效。
- 全部用 Web Audio 实时合成，**无外部音频依赖、无版权问题**，`AudioContext` 不可用或加载失败也不影响游戏运行。
- 技能美术全部用 Canvas / CSS / 程序化粒子绘制，**不依赖任何外部图片或第三方库**。
